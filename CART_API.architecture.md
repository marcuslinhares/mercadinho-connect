## 📋 Overview

The Shopping Cart API enables users to add/remove products, manage quantities, and persist cart state across sessions. The cart is backed by Supabase PostgreSQL and synced with local browser storage for offline capability.

**Key Goals:**
1. Fast add/remove operations (sub-100ms)
2. Persistent across sessions (DB + localStorage)
3. Auth-aware (users see only their own cart)
4. Real-time quantity updates
5. Cart totals calculation (subtotal, tax, shipping)

## 📊 Database Schema

### Table: `carts`

```sql
CREATE TABLE carts (
  id BIGINT PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  UNIQUE(user_id)
);

CREATE INDEX idx_carts_user_id ON carts(user_id);
```

**Purpose:** Tracks one cart per user. Soft cart state.

---

### Table: `cart_items`

```sql
CREATE TABLE cart_items (
  id BIGINT PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
  cart_id BIGINT NOT NULL REFERENCES carts(id) ON DELETE CASCADE,
  product_id BIGINT NOT NULL REFERENCES products(id) ON DELETE CASCADE,
  quantity INT NOT NULL DEFAULT 1 CHECK (quantity > 0),
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  UNIQUE(cart_id, product_id)  -- One row per product per cart
);

CREATE INDEX idx_cart_items_cart_id ON cart_items(cart_id);
CREATE INDEX idx_cart_items_product_id ON cart_items(product_id);
```

**Purpose:** Stores individual cart line items. Quantity tracked per product.

## 🔌 API Endpoints

### 1. POST `/api/cart/add`

**Purpose:** Add a product to the user's cart (or increase quantity if already present)

**Request Body:**
```json
{
  "product_id": 42,
  "quantity": 1
}
```

**Response (201 Created):**
```json
{
  "success": true,
  "message": "Product added to cart",
  "cart_item": {
    "id": 123,
    "cart_id": 5,
    "product_id": 42,
    "quantity": 1,
    "product": {
      "id": 42,
      "name": "Organic Milk",
      "price": 4.99,
      "image_url": "...",
      "stock": 50
    }
  }
}
```

**Status Codes:**
- `201 Created` → Success
- `400 Bad Request` → Missing product_id or quantity
- `404 Not Found` → Product not found
- `409 Conflict` → Product out of stock
- `401 Unauthorized` → Not authenticated

**Business Logic:**
- Check if product exists + has stock
- If cart_item exists for (cart_id, product_id), increment quantity
- Else, insert new row
- Return full product details (name, price, image)

---

### 2. POST `/api/cart/remove`

**Purpose:** Remove a product entirely from the cart

**Request Body:**
```json
{
  "product_id": 42
}
```

**Response (200 OK):**
```json
{
  "success": true,
  "message": "Product removed from cart",
  "cart_id": 5
}
```

**Status Codes:**
- `200 OK` → Success (or already absent)
- `401 Unauthorized` → Not authenticated

**Business Logic:**
- Delete cart_item row where cart_id = user's cart AND product_id = given
- If cart_item doesn't exist, return success (idempotent)

---

### 3. PUT `/api/cart/update-quantity`

**Purpose:** Update the quantity of a product in the cart

**Request Body:**
```json
{
  "product_id": 42,
  "quantity": 5
}
```

**Response (200 OK):**
```json
{
  "success": true,
  "message": "Quantity updated",
  "cart_item": {
    "id": 123,
    "product_id": 42,
    "quantity": 5
  }
}
```

**Status Codes:**
- `200 OK` → Success
- `400 Bad Request` → quantity <= 0 or invalid
- `404 Not Found` → Cart item not found
- `401 Unauthorized` → Not authenticated

**Business Logic:**
- If quantity > 0: UPDATE cart_items SET quantity = ? WHERE cart_id = user's AND product_id = ?
- If quantity = 0: DELETE (effectively a remove, but explicit semantics)
- Check product stock before allowing update (prevent overbooking)

---

### 4. GET `/api/cart`

**Purpose:** Fetch the full cart with all items and totals

**Query Parameters:** None

**Response (200 OK):**
```json
{
  "success": true,
  "cart": {
    "id": 5,
    "user_id": "uuid-123",
    "items": [
      {
        "id": 123,
        "product_id": 42,
        "product": {
          "id": 42,
          "name": "Organic Milk",
          "price": 4.99,
          "image_url": "...",
          "stock": 50
        },
        "quantity": 2
      },
      {
        "id": 124,
        "product_id": 99,
        "product": {
          "id": 99,
          "name": "Bread",
          "price": 2.50,
          "image_url": "...",
          "stock": 100
        },
        "quantity": 1
      }
    ],
    "totals": {
      "subtotal": 12.48,        // (4.99 * 2) + (2.50 * 1)
      "tax": 1.25,              // 10% of subtotal
      "shipping": 5.00,         // Fixed or based on subtotal
      "total": 18.73            // subtotal + tax + shipping
    }
  }
}
```

**Status Codes:**
- `200 OK` → Success (even if cart is empty)
- `401 Unauthorized` → Not authenticated

**Business Logic:**
1. Fetch cart for authenticated user
2. JOIN cart_items with products table
3. Calculate: subtotal = SUM(product.price * cart_item.quantity)
4. Calculate: tax = subtotal * 0.10 (store as constant)
5. Calculate: shipping = fixed $5 or 0 if free_shipping threshold met
6. Return full cart with all product details and totals

---

### 5. DELETE `/api/cart/clear`

**Purpose:** Empty the entire cart

**Request Body:** None

**Response (200 OK):**
```json
{
  "success": true,
  "message": "Cart cleared",
  "cart_id": 5
}
```

**Status Codes:**
- `200 OK` → Success
- `401 Unauthorized` → Not authenticated

**Business Logic:**
- DELETE all cart_items where cart_id = user's cart
- Keep the cart row itself (user's cart always exists for auth user)

## 🔐 Authentication & Authorization

**All endpoints require:**
1. Valid JWT token in `Authorization: Bearer <token>` header
2. Token extracted via Supabase `getAuth()` in Next.js middleware
3. Extract `user_id` from token claims
4. Scope: User can **only** access their own cart (enforce `cart.user_id === auth.user_id`)

**Implementation:**
- Middleware: Check JWT validity before route handler
- Route handler: Extract `user_id` from `req.user` (set by middleware)
- Query builder: Always filter by `user_id` (prevent horizontal access)

## 💾 Persistence Strategy

### Database (Supabase)
- **Single source of truth** for cart state
- Used for checkout, order creation, and cross-device sync
- Real-time updates to cart_items via Supabase Realtime (optional)

### Local Storage (Browser)
- **Optimistic updates** for fast UX (add to cart instant feedback)
- Syncs to DB asynchronously
- Key: `mercadinho:cart:<user_id>`
- Structure:
  ```json
  {
    "lastSyncAt": 1710172800000,
    "items": [
      { "product_id": 42, "quantity": 2 }
    ]
  }
  ```
- On app load: Fetch from DB, overwrite localStorage (DB is truth)
- On add/remove: Update localStorage instantly, POST to DB in background

## ⚡ Performance Targets

- **POST /add:** <100ms (cache product lookup)
- **POST /remove:** <50ms
- **PUT /update-qty:** <100ms
- **GET /cart:** <200ms (even with 100+ items)
- **Pagination:** Not needed (typical cart < 50 items)

**Optimization Strategies:**
1. Index cart_id + product_id on cart_items
2. Preload products in memory (Redis cache for frequently purchased items)
3. Batch updates in localStorage before sync to DB
4. HTTP/2 keep-alive for multiple requests
